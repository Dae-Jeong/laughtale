# 외부 연계 — Adapter와 Client

읽는 때: 외부 API·SDK 또는 다른 backend 서비스와의 통신을 변경할 때 읽습니다.
여기의 Adapter는 외부 통신을 위한 출력 Adapter이며 HTTP 입력·DB Adapter와 구분합니다.
공통 기준과 문서 선택은 [개발 규칙 진입점](../engineering-principles.md)을 따릅니다.

## 책임과 조립

| 구성 | 소유하는 책임 |
| --- | --- |
| Port | 업무에 필요한 행위·입력·결과·실패 계약을 내부 타입으로 정의합니다. provider endpoint나 SDK 타입을 노출하지 않습니다. |
| Adapter | Port를 구현하고 외부 필드·Enum·오류를 내부 의미로 변환합니다. 업무 정책을 결정하거나 다른 도메인 데이터를 변경하지 않습니다. |
| Client | HTTP/SDK의 주소·인증·직렬화·원시 응답 검증·timeout·연결 풀·통신 오류를 담당합니다. 업무 권한·한도를 판단하지 않습니다. |
| 조립 지점 | 실제 구현 또는 테스트 대역을 연결하고 생성·종료를 관리합니다. Service가 provider를 직접 생성하지 않습니다. |

실행 시 Service는 Port로 주입받은 Adapter를 호출하고 Adapter는 Client/SDK를 사용합니다.
Port는 별도 실행 서버가 아니라 계약입니다. 공유 Client는 동시 사용 안전성과 종료 처리를
확인하며 요청·트랜잭션 상태가 있는 객체는 singleton으로 공유하지 않습니다.

## 계약과 변환

- 원시 DTO·SDK 객체는 연계 경계 안에 유지하고 필요한 내부 값만 반환합니다.
- 필드 누락·알 수 없는 Enum·잘못된 형식의 처리 방식을 정합니다. 변환 실패를 빈 값이나 성공으로 숨기지 않습니다.
- 인증 실패, 한도 초과, 일시 장애, 계약 불일치, 처리 결과 불명을 내부 오류·결과로 구분합니다.
- 업무상 거절과 통신 실패를 구분합니다. 외부 HTTP 성공 코드만으로 우리 업무의 성공을 판정하지 않습니다.

## timeout·재시도·관측

- 연결·응답 대기 timeout과 전체 호출 시간 예산을 명시하고 구체 수치는 요구·측정으로 정합니다.
- 한 호출의 재시도 주체를 정해 SDK와 Client의 중첩 재시도를 막습니다. 대상 오류·최대 횟수·backoff·jitter·대기 상한을 정하고 provider의 rate limit·`Retry-After` 계약을 확인합니다.
- 비멱등 쓰기는 중복 방지 계약 없이 자동 재시도하지 않습니다. timeout이어도 외부에서는 성공했을 수 있으므로 결과 조회·대사·보상 등 복구 경로를 정합니다.
- 멱등 키를 지원하면 같은 업무 재시도에 같은 키를 사용하고 유효 기간·중복 응답 처리를 확인합니다.
- 회로 차단·동시 호출 제한·fallback은 실제 위험이 있을 때 도입합니다. 오래된 값이나 기능 제한을 정상 최신 결과로 숨기지 않습니다.
- 연계 대상·작업명·지연·성공과 실패 분류·재시도 횟수를 관측하고 요청·업무 식별자로 흐름을 추적합니다.

## 함께 읽을 조건

- 외부 날짜·금액·상태를 내부 업무 값으로 변환하면 [Domain](domain.md)을 읽습니다.
- DB 변경과 외부 실행이 함께 있으면 [트랜잭션](persistence.md#트랜잭션과-외부-실행)을 읽습니다.
- 내부 오류의 공개 HTTP 변환을 바꾸면 [HTTP API](http-api.md)를 읽습니다.
- 대역·계약 변환·sandbox 검증은 [Testing](testing.md)을 읽습니다.
