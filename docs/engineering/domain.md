# Domain — 상태와 업무 정책

읽는 때: Model, 불변조건, 상태 전이, 금액·시간·Enum, 실험 정책을 변경할 때 읽습니다.
공통 기준과 문서 선택은 [개발 규칙 진입점](../engineering-principles.md)을 따릅니다.

## Model과 정책

- Model은 이미 가진 값으로 판정 가능한 상태 전이와 불변조건을 직접 보호합니다. 변경은 `claim_call()`처럼 의미 있는 업무 메서드로 표현합니다.
- 상태는 Enum 등 명시적인 타입으로 표현하고 허용·금지 전이를 정의합니다. 상태 자체로 결정되는 종료 여부·그룹은 Enum이 소유하며 사용자·시간·한도 정책까지 넣지 않습니다.
- 핵심 엔티티는 안정적으로 유지하고 점수·추천·배분처럼 자주 바뀌는 정책을 분리합니다. 특징 계산과 그 특징으로 결정을 내리는 규칙도 구분합니다.
- 중요한 결정은 입력 시점·정책 버전·결과·사유를 추적할 수 있게 합니다. 기준값과 성능 예상치는 가설로 표시하고 실측으로 갱신합니다.
- 업무 상수는 소유 도메인에 두고, 업무 실패는 구체적인 예외·결과 타입으로 표현합니다.

## 값과 시간

- 십진 정밀도가 필요한 금액은 `Decimal`, `BigDecimal` 또는 최소 화폐 단위 정수를 사용합니다. 부동소수점 오차를 업무 규칙에 노출하지 않습니다.
- 로그를 포함한 사건의 발생 시각은 timezone-aware UTC로 저장·계산하고 입력·출력에서 사용자의 시간대로 변환합니다. 생일 같은 날짜와 현지 영업시간·반복 일정은 업무 의미 및 필요한 시간대를 보존하며 무조건 UTC timestamp로 바꾸지 않습니다. 날짜 구간의 기준 시간대도 명시합니다.
- 현재 시각은 서비스 공통 clock이나 주입한 clock으로 얻어 테스트에서 제어할 수 있게 합니다.
- Python 문자열 상태는 `StrEnum`을 기본으로 하며 멤버는 `UPPER_SNAKE_CASE`, 값은 `lower_snake_case`로 표현합니다. 외부 표준 코드의 지정 형식은 유지합니다.
